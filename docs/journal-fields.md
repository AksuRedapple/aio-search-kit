# 一次检索该记什么：14 个字段

> 判据：**每个字段都要能回答一个具体的排障问题**。答不上的字段不要加（它会稀释注意力）。

| # | 字段 | 类型 | 回答什么问题 |
|---|---|---|---|
| 1 | `query` | str | 用户**原话**是什么（不是改写后的） |
| 2 | `intent` | fact/fresh/nav/compare | 这次该不该要求时效性 |
| 3 | `queries[]` | str[] | **实际发出的**检索式（改写后），用于复盘"改写有没有跑偏" |
| 4 | `perQuery[{q,n}]` | obj[] | 每条检索式返回几条 —— 定位"哪条改写废了" |
| 5 | `cacheHit` | null/sqlite/mem | 有没有吃到缓存（**注意：长尾负载下它长期是 null，这是正常的**） |
| 6 | `calls` | int | 花了多少次付费调用 |
| 7 | `estCostCNY` | float | 这次花了多少钱（可做日预算闸） |
| 8 | `timing{rewrite,search,fetch}` | ms | 三段各多久 —— **改写常常是大头**（实测 p50 1260ms vs 检索 382ms） |
| 9 | `fetchStats{attempted,ok,retried,blocked,timeout}` | int | 抓取层的失败分布 |
| 10 | `raw[]` | obj[] | 排序前的原始结果（复盘"是不是排序丢了好东西"） |
| 11 | `dropped[]` | obj[] | 被丢掉的条目（复盘"卫生规则是不是过严"） |
| 12 | `degraded[]` | str[] | 降级要**有名字**：`hygiene-dropped:5` 比 `degraded:true` 有用得多 |
| 13 | `officialBoost` | float | 这次用了多少官方域加成（可回滚的旋钮） |
| 14 | `elapsedMs` | ms | 端到端（与 #8 的差 = 排队与序列化开销） |

## 三条使用纪律

1. **原话与实际动作分开记**（#1 vs #3）：否则你无法区分"用户问得怪"和"改写跑偏了"。
2. **丢弃必须有账**（#11 + #12）：丢了 40% 却不知道为什么丢，这个指标等于没有。
3. **成本按次记**（#7）：205 次累计 ¥1.32，单次 ¥0.0065 —— 没有这个数，"贵不贵"只能靠感觉。
