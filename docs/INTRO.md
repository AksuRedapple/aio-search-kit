# 这个仓是什么，适合谁，别期待什么

> 发布版导言。三分钟读完，决定要不要往下看。

## 一句话

**给 coding agent 的搜索，装一层「缓存 + 配额 + 降级 + 对账」。**

如果你同时在用 Claude Code、Codex、opencode（或自己的 agent），你大概已经遇到：每个 harness 各有一套搜索，
缓存不共享、出处不一致、**这个月花了多少钱没人说得清**。这个仓把那三件事收拢到一个本机服务里。

## 适合谁

- **同时用 2 个以上 coding agent**，并且觉得"每个都自带搜索"很浪费的人；
- 想给 agent 的检索**加预算闸**（按次数 + 按钱）的人；
- 需要一个**统一出处**（每条结果带 url 和抓取时间）来做后续引用/审计的人；
- 喜欢小而可读实现（588 行、零第三方依赖）而不是一个大框架的人。

## 别期待什么

| 它不做 | 为什么 |
|---|---|
| **不抓正文、不生成答案** | 那是 RAG 的活，不是搜索底座的活 |
| **不是公网服务** | 只绑 `127.0.0.1`，天然没有鉴权；别暴露出去 |
| **不是可信计量** | 配额是**本地自记账**，防的是"我忘了控制"，不是防攻击 |
| **不保证免费额度稳定** | 默认的 keyless provider（Firecrawl）按 IP 限流，随时可能收紧 |
| **不是搜索引擎** | 它没有自己的索引；它编排别人 |

## 它凭什么值得看

不是因为它功能多，而是因为这些判断都有实测支撑，并且写在同一仓的 `docs/` 里：

- **降级要有名字**（`quota-exceeded` / `provider-fail`），不是一个 `degraded:true`；
- **缓存键决定命中率量级**：长尾负载下"同问题问两次"几乎不存在，纯精确匹配命中率≈0；
- **没出处的条目不入库**，否则是在造"没证据的记忆"；
- **测试流量要能被剔除**（`origin=test`），否则命中率会被压测刷高；
- **评测不是跑过一次就有闸**：要有基线、查询集哈希、阈值按题量取粒度。

每条背后都有一篇现场文章，索引在 [`READINGS.md`](READINGS.md)。
