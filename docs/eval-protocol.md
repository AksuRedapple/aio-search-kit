# 评测口径：grounded 三判据 + 两口径 + 伪失败

## 一、三判据（一条全过才算 grounded）

1. **答案非空**，且不是"材料不足"；
2. **每条 `[n]` 引用都指向本轮真实返回过的结果**（引用落地）；
3. **至少一条引用是非聚合站**（厂商文档/官方仓库/论文，而不是 CSDN/知乎/博客园这类）。

第 2 条是这套口径的核心：它把"模型答对"和"**检索到**"分开了。没有它，分数只是模型分数，不是检索分数。

## 二、两口径

| 口径 | 分母 | 用途 |
|---|---|---|
| `overall` | 全部查询 | 对外汇报 |
| **`web_answerable`** | 剔除"需要本地/个人上下文"的查询 | **闸门口径** |

要剔除的例子：`我的磁盘格式怎么转`、`我的浏览器搜不出东西`、`x = torch.tensor(...)`（无上下文代码片段）。
**理由**：这些题网络本来就不该答，算进分母会让通过率被"必然失败项"拉低，闸门在关键时刻失灵。

## 三、伪失败（必须识别，否则会去修不存在的 bug）

实测案例：`告诉我本地 macmini 安装 jupyter 的手动步骤，…出问题怎么排查`
- 判 insufficient；
- 但直接跑检索，返回的是 setapp / phoenixnap 的 Mac 安装指南 —— **检索是好的**；
- 真因：**多段问题**（安装 + 排错），而判据要求"材料足以回答整个问题"，材料只覆盖前半段。

处置：多段查询要么拆段，要么在判据里加第 4 档 `PASS-partial`。**不要把它算作产品失败。**

## 四、闸门

```
N=20 bash tools/regress.sh
判据：web_answerable 口径下降 >10 个百分点 → exit 1
仪器失败（缺 key / 跑挂）→ exit 2（不算产品失败）
```

首次基线示例：overall 8/12 = 66.7%，web_answerable 8/9 = 88.9%，中位 3045ms。

## 五、诚实边界

- grounded 需要一次 LLM 判 + 抓页面，**只能离线跑**；
- n 小时噪声大（12 条里一条翻转就是 8 个百分点）；
- `web_answerable` 标签是人工的，主观——它的价值是让口径**显式**，不是让口径客观。
